## 0. 結論（先に言う）

**「かんたんモード」は現状ほぼ機能していない。** 理由は3つ:

1. **デフォルトOFF** — 初心者は最初からGit用語モードで始まる（`simple-mode-context.tsx:33`）
2. **フロー画面には一切配線されていない** — `src/components/flow/**` に `useSimpleMode` の import はゼロ。かんたんモードONでも `.yaml`・生JSON・「正本は YAML/Git です…Proposal…コミット」は全部表示される
3. **効いている4ファイルでも文言差し替え程度** — 情報量・操作数は減らない

したがって方針は「かんたんモードを強化する」ではなく、**「簡単がデフォルト、技術詳細はopt-in」に反転させ、要素そのものを削る**こと。モードの追加はしない。

もう1つ重要な発見: **バグで初心者体験が既に壊れている**。作成時に入力したPlan項目が二度と表示されない、効果確認を保存しても再訪時に空に見える、「効果なし」を選ぶと課題を完了する手段が消える——これらは簡素化以前の問題で、最優先で直す（§2 P0）。

「困ったら検索窓に聞けば分かる」構想（AIヘルプ）は有効だが **P2**。ボタンが存在しない・ガイドが実画面と食い違う状態でヘルプAIを載せても、AIが「存在しないボタンを押せ」と案内するだけになる。土台→減量→ヘルプの順で積む。

## 2. プラン

### 設計原則（全フェーズ共通）

1. **簡単がデフォルト、詳細はopt-in** — 「かんたんモード」を廃止し「詳細モード（技術情報を表示）」に反転。初心者は何もしなくても簡単な画面
2. **1つの物に1つの名前** — 「改善カード」に統一（課題/Issue廃止）。ステータス語彙も1系統に
3. **道を1本にする** — 各作業に推奨経路1つ。他の経路は消すのではなく「詳細ツール」へ格納（拡張として残す）
4. **行き止まりゼロ** — どの状態からも「次にすること」ボタンが1つ見えている
5. **破壊的操作は必ず確認、非破壊は確認なし** — 「保存」の意味を全経路で統一
